2.1.0.25.119

No action required from operators.

- A node no longer holds free workers back for seats it has given up, so after a restart that follows a long downtime its free workers can take new seats; no operator action. (#1345)
- The health report and the node manager now show seat, shard, store and reachability conditions as notices, including a store whose fsync is slow (the figure and its bound); no operator action. (#1314)
- Storage snapshot encoding uses all of a node's CPUs again, about 5x faster on large leaves than .118 (it had fallen to about 1.3 of 6 CPUs); no operator action. (#1346)
- A node no longer rewrites and syncs each reserved sector's unchanged lease and mapping at every GLOBAL frame, cutting disk syncs and writes on nodes with many sectors; no operator action. (#1348)
- Storage commitments and proof workers keep large working sets within a memory budget, spilling to a scratch file when over it (macOS memory use) (#1350)
- Paced shields (`token shield-all`, the node manager's shield) now pause only while the GLOBAL head is unchanged for 120 s or more, not whenever GLOBAL is slow (#1351).
- `token mint --wait` keeps waiting through a slow or lost status read until `--wait` ends, and the node answers the status read without waiting on GLOBAL frame execution; a final error names the saved authorization's `--claim` command; no operator action. (#1353)
- A node syncs its local vote journal to disk only for the votes a restart needs, not for every finalize vote and vote share, cutting disk syncs on busy nodes; votes and their order are unchanged; no operator action. (#1349)
- Shards that lost their seal after missing a storage snapshot frame (16 of 110 stalled since Nov 11) produce again from epoch 1484 (GLOBAL frame 1,068,480): GLOBAL admits their headers until they seal again. Archives must run this release before epoch 1484; regular nodes should upgrade so stalled shards recover as their members do. (#1354)
