2.1.0.25.122

No action required from operators.

- Logging: each storage window's seat summary is logged once the window ends (#1383)
- Logging: storage proof warnings name every archive that refused (#1392)
- Storage: epoch proofs get 8 MiB of each GLOBAL proposal, so settlements ride sooner and fewer miss their window (#1397)
- Logging: proofs dropped from a full retry queue count in their window's summary and log once (#1396)
- Client: a refused release-source change now says that rerunning it enables auto-update again (#1394)
- Client: wallet history shows past actions from the node's action log. (#1378)
- Engine: logs GLOBAL frame execution time by message type. (#1399)
- Engine: a settlement batch leaves out seats that are already settled. (#1400)
- GLOBAL proposals now carry held storage epoch proofs in turn until their window closes; a relayed or second proof is no longer dropped after its sender was told it was accepted (#1395)
- Nodes no longer resend a storage epoch proof holding a seat already settled, which made archives drop narrower proofs and let their seats expire unsettled (#1398)
- Mac nodes run a frame's proof check alone when the system is under memory pressure (#1403)
- qclient node diagnostics: the health report shows free disk space and the machine it runs on. (#1404)
- Nodes listen on IPv6 by default and include extra bootstrap peers. (#1406)
- A dual-stack archive now counts as one archive: messages go to it once, its outage starts only when no endpoint connects, and a node without IPv6 no longer warns every 10 min. (#1407)
- macOS nodes log host memory (total, available, swap and page breakdown) in the periodic memory snapshot; log-only. (#1410)
- A node whose store hits a corrupt block (checksum mismatch) now exits after 5 minutes so its service manager restarts it, instead of staying up and refusing writes; repeated GLOBAL frame write failures log once at onset, as a count every 10 minutes, and at recovery. An archive seeing CORRUPTION should keep and copy its store and check disk and RAM, not discard or resync it. (#1412)
